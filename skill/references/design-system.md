# 设计系统（Design System）

> 本文件是 AI 撰写 HTML 幻灯片时的**唯一设计依据**。所有颜色、字体、字号、间距必须取自本文件，并写入 `tokens.json` 冻结。禁止在页面里发明本文件之外的 token。
>
> 画布：**960 × 540 CSS px**（转换引擎按 1px = 0.75pt 映射为 720 × 405pt 的 16:9 页面）。所有坐标、字号、间距都以 px 计。
> 页面根元素：`<body>` 必须 `width:960px; height:540px; margin:0;` 且 `lang="zh-CN"`（缺失会触发校验错误 `lang-missing`）。

---

## 0. 设计令牌总览（tokens.json 结构）

每套配色 + 字体 + 字号阶梯组合成一个冻结的 `tokens.json`。字段名固定，引擎按此读取：

```json
{
  "pageSize": { "w": 960, "h": 540 },
  "palette": {
    "bg": "#F5F7FA", "surface": "#FFFFFF", "primary": "#1F4E79",
    "accent": "#C9A227", "text": "#1A1A1A", "muted": "#6B7280",
    "primaryLight": "#3A6EA5", "primaryDark": "#14365C",
    "accentLight": "#DDBB4F", "accentDark": "#A07F1B",
    "surfaceAlt": "#EDF1F6", "border": "#D8DEE6"
  },
  "fonts": {
    "heading": "Microsoft YaHei", "body": "DengXian",
    "latin": "Segoe UI", "mono": "Consolas"
  },
  "typeScale": {
    "h1": 56, "h2": 36, "h3": 26, "body": 17, "small": 13
  },
  "spacing": 8
}
```

- `palette` 必含：`bg` / `surface` / `primary` / `accent` / `text` / `muted`，以及深浅变体 `primaryLight` / `primaryDark` / `accentLight` / `accentDark`（可再加 `surfaceAlt`、`border`）。
- `fonts` 只允许本文件 §2 列出的 Windows 自带字体。
- `typeScale` 取值必须落在 §3 的字号阶梯区间内。
- `spacing` 恒为 8（8px 网格，见 §4）。

## 1. 配色系统（4 套 Palette）

> 选择规则：先定**受众与场合**，再选套系。同一份 deck 只允许一套配色（可微调 accent 深浅变体），禁止混搭两套。
> 每套给出完整 hex 色板与使用比例。**accent 面积 ≤ 10%**（见 §5 反 AI 味规则）。

## 2. 字体搭配（Typography）

> 只允许 Windows 自带字体（引擎按英文名解析，PowerPoint 才能打开）。**禁止** `@font-face`、禁止任何未列出的字体。

| 角色 | 中文字体 | 拉丁字体 | 说明 |
|---|---|---|---|
| 标题（h1–h3） | **微软雅黑 Bold**（`Microsoft YaHei`，`font-weight:700`） | `Segoe UI` | 标题一律加粗；英文数字随标题走 `Segoe UI` |
| 正文（p / li / a / span） | **等线**（`DengXian`）或 微软雅黑（`Microsoft YaHei`） | `Segoe UI` / `Arial` | 正文默认 `font-weight:400`，不滥用加粗 |
| 衬线点缀（引文 / 强调句） | 微软雅黑 | `Georgia` | 拉丁衬线用于引文、署名，营造对比 |
| 等宽（代码 / 数字表格） | 微软雅黑 | `Consolas` | 代码块、对齐的数字列 |

**font-family 写法（引擎按栈解析，第一个已安装族生效）**：

```css
/* 标题 */
font-family: "Microsoft YaHei", "Segoe UI", sans-serif;
/* 正文 */
font-family: "DengXian", "Microsoft YaHei", "Segoe UI", sans-serif;
/* 等宽 */
font-family: "Consolas", "Microsoft YaHei", monospace;
```

**规则**：
- 中文字体一律写**英文名**（`Microsoft YaHei`、`DengXian`），不要写 `微软雅黑` 中文名进 CSS。
- 含 CJK 字符的 run，引擎会提升到第一个 CJK 可用族；页面必须 `lang="zh-CN"`。
- 生僻字（如 `𠀀`）雅黑缺字时引擎会回退并告警——正文优先用常用字。
- 东亚备用：如确需宋体/楷体效果，可用 `SimSun`（宋体）、`KaiTi`（楷体），仅限装饰性引文，不用于正文。

## 3. 字号阶梯（Type Scale，960×540 画布）

> 层级靠**字号 + 字重**，不靠颜色数量（见 §5）。同一页最多出现 4 档字号。

| 档位 | 区间（px） | 推荐值 | 行高 line-height | 用途 |
|---|---|---|---|---|
| h1 | 48–64 | 56 | 1.15–1.25 | 封面主标题、章节大标题（每页最多 1 个） |
| h2 | 32–40 | 36 | 1.2–1.3 | 页内区块标题 |
| h3 | 24–28 | 26 | 1.3–1.4 | 卡片标题、小节标题 |
| body | 16–18 | 17 | 1.5–1.7 | 正文、列表 |
| small | 12–14 | 13 | 1.4–1.5 | 注释、页脚、图例、来源 |

**规则**：
- 封面 h1 用 56–64；内容页 h1 用 48–52（避免与页眉冲突）。
- 正文行高 ≥ 1.5（中文阅读舒适）；标题行高 1.15–1.3。
- 数字与单位同 run 同字号；图表轴标签用 small 档。
- 一页文字总量：内容页正文 ≤ 120 汉字 / 页（高密度页 ≤ 500 汉字，仅限压力测试页）。

## 4. 8px 间距网格（Spacing Grid）

> 所有 margin / padding / 元素间距必须是 **8 的整数倍**：8 / 16 / 24 / 32 / 40 / 48 / 56 / 64。禁止 5、10、15、20 这类非 8 倍数。

| Token | 值 | 典型用途 |
|---|---|---|
| s-1 | 8px | 图标与文字间距、标签内边距 |
| s-2 | 16px | 卡片内边距、列表项间距 |
| s-3 | 24px | 区块间距、卡片间距 |
| s-4 | 32px | 页边距（左右）、标题与正文间距 |
| s-5 | 40px | 大区块间距 |
| s-6 | 48px | 页眉与内容间距 |
| s-7 | 56px | 封面标题与副标题间距 |
| s-8 | 64px | 封面大留白、页脚上方留白 |

**页面边距约定**：左右 48px（`padding: 0 48px`），顶部 40px，底部 32px。封面可放宽到 64px 大留白。

**留白节奏**（§5 反 AI 味）：内容页至少保留 1 处 ≥ 40px 的"呼吸区"；禁止所有元素贴满画布。

## 5. 反 AI 味规则（Anti-AI-Slop Rules）

> 这些是**硬规则**，违反即返工。AI 生成页面最容易踩的坑，全部列在这里。

1. **禁三等分卡片默认阵**：不要一上来就"三张等宽卡片横排"。三等分是 AI 默认动作，一眼假。
   - 替代：2 列（左文右图 / 左图右文）、4 列窄条、上下分层、时间轴、单列大数字、左右对比。
   - 若确需 3 项并列，必须打破等宽：中间卡片加宽或加高、两侧用 `surfaceAlt` 底、中间用 `surface` 底 + `border`。
2. **禁紫蓝渐变默认**：`#6C5CE7 → #A29BFE` 这类紫蓝渐变是 AI 标志性配色，**默认禁用**。
   - 渐变只允许：同色系深浅渐变（如 `primary → primaryDark`）、或透明到纯色的遮罩渐变。
   - 渐变容器必须标 `data-ppt-raster`（引擎栅格化），且**渐变上不得有文字**（见 html-constraints.md `raster-with-text`）。
3. **accent 面积 ≤ 10%**：强调色只用于关键数字、按钮、下划线、小图标。整页 accent 色块面积合计不得超过页面面积的 10%。一页 accent 出现 ≤ 3 处。
4. **层级靠字号字重，不靠颜色数量**：一页最多 3 种颜色（bg/surface 不算）。层级用 h1→h2→h3→body 的字号差 + 加粗表达，不要用 5 种颜色区分 5 个层级。
5. **留白节奏**：每页至少 1 处 ≥ 40px 的空白区；元素不贴边、不贴满；卡片间距统一 24px。留白是设计的一部分，不是浪费。
6. **禁 emoji 当图标**：`📈` `🚀` `✅` 一律禁止。图标用 CSS 形状（圆点、方块、竖条、对勾用 `✓` 字符或 SVG 形状）或干脆不用。emoji 在 PowerPoint 里渲染不可控，且显得廉价。
7. **禁装饰性渐变文字**：文字上禁止 `background-clip:text` 渐变（校验错误 `gradient-on-text`）。文字颜色只用纯色 token。
8. **禁动画与悬浮**：`animation`、`transition`、`position:fixed/sticky`、`backdrop-filter`、CSS `columns` 全部禁止（校验错误，见 html-constraints.md）。页面是静态的。
9. **阴影克制**：卡片阴影只用于"浮在照片/色块上"的场景；等宽卡片网格一律无阴影。一页最多 2 个带阴影元素。
10. **对称 ≠ 设计**：不要每页都居中对称。封面可居中，内容页多用左对齐 + 非对称留白。

## 6. 版式模式（Layout Patterns，按 data-ppt-role）

> 每个页面必须声明 `data-ppt-role`（cover / toc / section / content / data / closing），并按对应模式排版。ASCII 草图中 `[ ]` 为区块，`#` 为强调色块，`·` 为留白。

### 6.1 cover（封面）

```
┌────────────────────────────────────────────┐
│  ········································  │
│  ·  ██  (primaryDark 竖条 8px 宽)          │
│  ·  ██  h1 主标题（56px Bold）             │
│  ·  ██  ································   │
│  ·  ██  h3 副标题 / 一句话说明（muted）     │
│  ·  ····································   │
│  ·  ····································   │
│  ·  ····································   │
│  ·  small 日期 · 汇报人 · 部门（muted）     │
│  ·  ─── accent 细线 64px 宽（≤10%）        │
└────────────────────────────────────────────┘
```

要点：标题左对齐（或居中），副标题与标题间距 24px，底部信息用 small + muted。accent 只出现在一条细线或一个小色块。

### 6.2 toc（目录）

```
┌────────────────────────────────────────────┐
│  h2 目录（36px Bold）                       │
│  ────────────────────────────────────────  │
│  · 01  第一部分标题  ················ 页码  │
│  · 02  第二部分标题  ················ 页码  │
│  · 03  第三部分标题  ················ 页码  │
│  · 04  第四部分标题  ················ 页码  │
│  ········································   │
│  · 当前章节序号用 primary 加粗，其余 muted   │
└────────────────────────────────────────────┘
```

要点：条目间距 24px；序号用等宽数字（Consolas）或 primary 色；**不要**做成三列卡片阵。

### 6.3 section（章节过渡页）

```
┌────────────────────────────────────────────┐
│  ········································   │
│  ········································   │
│  ·  ██  h1 章节标题（48px Bold）           │
│  ·  ██  ································   │
│  ·  ██  h3 章节导语一句（muted）           │
│  ·  ····································   │
│  ·  ····································   │
│  ·  ····································   │
│  ·  small 章节编号 02 / 05（muted）        │
└────────────────────────────────────────────┘
```

要点：极简，只放章节号 + 标题 + 一句导语。大留白（上下 ≥ 64px）。可加一个 `primary` 小方块或竖条作视觉锚点。

### 6.4 content（内容页：文字 / 列表 / 图文）

```
┌────────────────────────────────────────────┐
│  h2 页标题（36px Bold）                     │
│  ── primary 短横线 48px（标题下）           │
│  ········································   │
│  ┌──────────────┐  ┌────────────────────┐  │
│  │ h3 小节标题   │  │ h3 小节标题         │  │
│  │ · 要点一      │  │ 正文段落……          │  │
│  │ · 要点二      │  │ 正文段落……          │  │
│  │ · 要点三      │  │                    │  │
│  └──────────────┘  └────────────────────┘  │
│  ········································   │
│  small 页脚：页码 · 来源（muted）           │
└────────────────────────────────────────────┘
```

要点：双栏（左窄右宽）或单栏；卡片间距 24px；列表项间距 16px；页脚 small + muted。**不要**三张等宽卡片。

### 6.5 data（数据页：图表 / 大数字）

```
┌────────────────────────────────────────────┐
│  h2 数据标题（36px Bold）                   │
│  ········································   │

│  └────────────────────────────────────┘    │
│  ········································   │
│  ┌────────┐ ┌────────┐ ┌────────┐          │
│  │ 56px    │ │ 56px   │ │ 56px   │          │
│  │ 98%     │ │ ¥120万 │ │ 3.2×   │          │
│  │ small   │ │ small  │ │ small  │          │
│  │ 完成率   │ │ 节省成本 │ │ 效率提升 │       │
│  └────────┘ └────────┘ └────────┘          │
│  ········································   │
└────────────────────────────────────────────┘
```

要点：图表区占主导（≥ 60% 宽度）；关键数字用 h1 档（48–56px）+ primary 色，标签 small + muted；数字与标签间距 8px。图表颜色取自 tokens（主系列 primary，次系列 accentLight）。

## 8. 旁门左道设计方法论（PangMen ZuoDao / 邵云蛟）

> 来源：旁门左道PPT 公众号（邵云蛟）公开方法论的提炼，与本文档 §1-§7 的令牌体系配合使用。冲突时以本项目的令牌白名单（§0-§4）为准——方法论指导"怎么选"，令牌约束"能用什么"。

### 8.1 配色方法论

**主色系统（每套 deck 只有一套）**：先定 1 个主色（决定整套 PPT 的气质），再配 1 个辅助色（衬托主色、承载次级信息），最后 1 个强调色（只用来点亮关键信息）。主色不是越鲜艳越好，而是要和内容气质匹配：汇报类适合蓝/灰/深绿等稳重色，科技类适合深色底+高亮色，文化/人文类适合低饱和暖色或墨色系。

**6:3:1 面积配比**：一页内主色约 60%（背景、大面积色块）、辅助色约 30%（容器、图形、次级文字）、强调色约 10%（关键数字、下划线、图标点缀）。强调色超过 10% 就不再"强调"，页面会乱。

**色轮三法（需要新配色时按序尝试，角度为色轮上的间距）**：
1. **近似色配色法**——色轮上相邻的颜色（邻近色 ≤60°，如蓝+蓝绿）。最和谐、最不易出错，适合不想用太多颜色的页面；用明度深浅做层次。
2. **对比色配色法**——色轮上 180° 对角的互补色（如蓝+橙、红+青）。对比极强，只适合做强调：在主色背景上用对比色点亮关键内容，绝不大面积铺。（中差色 ~90°、对比色 ~120° 介于两者之间，视觉冲击强但更难控制，慎用。）
3. **分散对比色配色法**——一组近似色打底 + 一个对比色强调（如蓝绿系打底、橙色强调）。这是旁门左道最推荐的方法：既有和谐的主色群，又有明确的视觉焦点。本项目的 4 套 Palette（§1）均按此法构建。

**十字正交法（旁门左道"一根线"配色）**：把配色拆成 **色相 × 明度** 两条正交轴——同一条色相线上只动明度（一种颜色做出多层次），不同色相间保持明度对齐。配色"土、乱、没层次"的根因几乎都是明度失控：先排明度阶梯（谁最亮、谁最暗、谁居中），再定色相；单色系靠明度渐变出层次（如 Apple 发布会式深蓝→浅蓝），多色系则要求各色相明度一致才能和谐。图表和流程图里尤其适用：同一系列用明度渐变区分级别，跨系列用色相对比。

**排版为主、配色为辅**：排版才是决定页面好不好看的主要因素，配色只能锦上添花。页面难看时先查 §8.2 四原则（尤其对比与对齐），再怀疑配色——顺序不能反。

**现成取色来源（优先级从高到低）**：① 品牌 logo/VI 取色（企业主色调，用取色器取）→ ② 成熟作品/官网取色 → ③ 配色工具生成（coolors、palettable 等，输入一个主色自动匹配一套）。拿到色后仍要走 §0 的 tokens.json 白名单，不得直接在 HTML 里写死。

**明度深浅对比**：白底黑字永远是最稳的搭配；深色底配浅色文字同理。深浅搭配产生"明度反差"，是比色相更可靠的层级手段——层级拿不准时先调明度，再考虑加色相。

### 8.2 排版四原则（亲密 / 对齐 / 对比 / 重复）

源自《写给大家看的 PPT 设计书》，是专业 PPT 团队公认的排版标准。四原则与本项目 §4 的 8px 网格、§6 的版式模式配合：

1. **亲密（Proximity）**——相关的元素靠近成组，无关的元素拉开距离。观众第一眼看到的是"组"而不是"散点"。落地：一个逻辑块的标题、正文、注释之间用小间距（8/16px），块与块之间用大间距（32/48px）；绝不允许"所有元素等距平铺"。
2. **对齐（Alignment）**——页面上每个元素都应与另一元素存在视觉联系，不能随意摆放。落地：正文左对齐、标题可居中；一页内至少有一条贯穿的主对齐线（通常 left=48px）；多个元素纵向排列时严格共享同一 x 坐标（8px 网格天然保证）。
3. **对比（Contrast）**——用差异制造重点：字号大小对比、字重粗细对比、颜色深浅对比、色块虚实对比。页面"平"的原因几乎都是对比不足。落地：同一信息层级内保持一致，跨层级必须拉开（如 h1 56 vs body 17）；重点数据用大字号+主色，辅助说明用小字号+muted。
4. **重复（Repetition）**——整套幻灯片重复使用同一套设计元素：配色方案、字体组合、装饰元素、版式位置。"重复不代表单调，而是在变化中寻找统一"——这是专业感与品牌感的来源，能显著降低观众认知成本。落地：每页复用同一 tokens；标题下统一加同规格下划线；页眉/页脚/页码的位置跨页一致；章节页用同一种版式。

### 8.3 文字提炼（少即是多）

- **一页一个核心信息**：先问"这页只留一句话会留哪句"，把它做成页面的视觉重心（大字号/主色/独立区域），其余内容都是它的支撑。
- **关键词替代句子**：能 8 个字说完的不写 20 个字。正文段落超过 3 行就必须拆：拆要点、拆图表、拆到下一页。
- **大字报式强调**：把最关键的词/数字放大到 h1 档（48-64px），其余用 body 档——字号对比是最便宜的视觉张力。
- **多文字页的正路**：实在删不掉的大段文字，按"人民日报式多图文排"处理：双栏分栏、行距 1.5+、明确段间距，绝不让文字挤成一面墙（本项目对应 §6.4 content 双栏模式 + 高密度页规范）。
- **层级三件套**：标题（h 档、粗、深色）→ 正文（body 档、常规、text 色）→ 注释/来源（small 档、muted 色）。三个层级齐了，页面自然不乱。

### 8.4 图表设计规范

- **按意图选图表**：趋势变化 → 折线图；数量对比 → 柱状图；占比构成 → 饼/环（本项目 MVP 仅支持 bar/line，占比用条形对比替代）；流程/循环关系 → 用 div+CSS 形状拼装（见 §6.4），不用 <table>。
- **一图一结论**：图表旁边必须有一句"数据解读"（这图说明什么），不让观众自己猜。标题写结论而不是写"XX 图"（"Q3 营收增长 18.6%" 优于 "Q3 营收柱状图"）。
- **图表配色继承主色系统**：系列色来自 tokens 的 palette（主系列 primary，次系列 accentLight，见 §0），绝不给图表单独发明颜色；需要突出的那根柱/那条线用强调色，其余用弱化色。
- **做减法**：去掉与结论无关的网格线、图例、数据标签；坐标轴文字用 small 档 muted 色。观众 3 秒内应看到"哪个系列在哪个点最高/最低"。
- **数字规范**：大数字用 h1/h2 档 + primary 色；单位写进标签（"营收（万元）"）而不是每个数字后面重复。
